# DeepSeek Bridge

DeepSeek Bridge подключает ваш обычный аккаунт на сайте DeepSeek к Claude Code, OpenCode и другим программам через локальный API. Bridge запускается на вашем компьютере, использует уже открытую веб-сессию DeepSeek и предоставляет OpenAI- и Anthropic-совместимые маршруты по адресу `http://127.0.0.1:9655`.

> Это не официальный API DeepSeek. Проект использует внутренний Web API сайта `chat.deepseek.com`. DeepSeek может изменить внутренние маршруты, PoW, WASM, ограничения или формат ответов — после такого обновления Bridge может временно перестать работать.

## Что понадобится

- Windows 10 или Windows 11;
- Node.js 20 или новее;
- Google Chrome;
- ваш собственный аккаунт DeepSeek;
- Claude Code или OpenCode — только если вы хотите запускать эти CLI-агенты.

Node.js лучше устанавливать в LTS-версии с [официального сайта](https://nodejs.org/en/download). Chrome можно скачать на [официальной странице](https://www.google.com/chrome/download-chrome).

## Как скачать

1. Откройте [репозиторий DeepSeek Bridge](https://github.com/serickprime/FreeDeepseekAPI).
2. Нажмите зелёную кнопку **Code**.
3. Выберите **Download ZIP**.
4. Откройте скачанный архив и нажмите «Извлечь все».
5. Распакуйте программу, например, в `D:\AI\DeepSeekBridge`.

Не распаковывайте её в `C:\Program Files`: Windows может потребовать дополнительные права.

## Первый запуск и авторизация

1. Откройте папку программы.
2. Дважды нажмите [START_DEEPSEEK.cmd](START_DEEPSEEK.cmd).
3. Подождите, пока откроется панель `http://127.0.0.1:9655/setup`.
4. Нажмите **Войти в DeepSeek**.
5. В отдельном окне Chrome войдите в свой аккаунт. CAPTCHA и 2FA проходите самостоятельно.
6. Отправьте в DeepSeek сообщение `ok` и дождитесь ответа.
7. Вернитесь в окно терминала и нажмите Enter.

Bridge сохранит данные текущей сессии в `deepseek-auth.json`. Логин и пароль не сохраняются, а token и cookie не показываются в терминале.

Если панель не открылась автоматически, откройте в браузере `http://127.0.0.1:9655/setup`.

## Диагностика через doctor

После авторизации нажмите **Запустить диагностику** в панели или выполните в папке программы:

```powershell
npm run doctor
```

Doctor — это не только проверка auth-файла. Он последовательно проверяет:

1. наличие и корректность `deepseek-auth.json`;
2. наличие token и cookie;
3. доступность DeepSeek Web;
4. создание отдельной удалённой сессии;
5. получение PoW challenge;
6. загрузку актуального WASM;
7. компиляцию WASM;
8. решение PoW;
9. реальный короткий completion-запрос;
10. получение streaming-ответа;
11. разбор SSE-потока;
12. наличие диагностического маркера в финальном тексте.

Doctor отправляет один короткий диагностический запрос в ваш аккаунт. Он не запускается автоматически обычными offline-тестами.

HTTP 403 от главной страницы `chat.deepseek.com` может означать блокировку публичной страницы, хотя DNS, TLS и соединение работают. Такой статус сам по себе не доказывает, что авторизация сломана. Но HTTP 401 или 403 от внутреннего API при создании сессии или completion обычно означает, что нужно вручную повторить:

```powershell
npm run auth
```

## Выбор модели

В панели доступны только режимы, которые Bridge считает рабочими для текущего DeepSeek Web API:

| Модель | Для чего подходит |
| --- | --- |
| `deepseek-chat` | Обычные быстрые ответы без reasoning и поиска |
| `deepseek-reasoner` | Задачи с reasoning; рекомендуемый режим для CLI и инструментов |
| `deepseek-chat-search` | Chat со встроенным поиском DeepSeek |
| `deepseek-reasoner-search` | Reasoning со встроенным поиском DeepSeek |

`deepseek-expert` и `deepseek-v4-pro` сейчас недоступны: текущий Web API возвращает для этих режимов пустой ответ. Bridge не выдаёт их за работающие модели.

## Запуск Claude Code через панель

1. Установите Claude Code.
2. Запустите `START_DEEPSEEK.cmd`.
3. В панели выберите модель.
4. Укажите папку проекта вручную или нажмите **Выбрать папку…**.
5. Нажмите **Запустить Claude Code**.

Откроется новое окно терминала в выбранной папке. Если кнопка неактивна, установите Claude Code, перезапустите Bridge и обновите панель через `Ctrl+F5`.

Ручной запуск из PowerShell:

```powershell
$env:ANTHROPIC_BASE_URL="http://127.0.0.1:9655"
$env:ANTHROPIC_AUTH_TOKEN="local-key"
$env:CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY="1"
claude --model deepseek-reasoner
```

`local-key` здесь является локальным служебным значением, а не ключом вашего аккаунта DeepSeek.

## Запуск OpenCode через панель

1. Установите OpenCode.
2. В панели выберите модель и папку проекта.
3. Нажмите **Запустить OpenCode**.

Панель использует готовый [opencode.json](opencode.json) и запускает OpenCode в выбранной папке. Если кнопка неактивна, перезапустите Bridge после установки OpenCode и обновите страницу через `Ctrl+F5`.

Ручной запуск из папки Bridge:

```powershell
$env:OPENCODE_CONFIG=(Resolve-Path ".\opencode.json")
opencode --model deepseek-web/deepseek-reasoner
```

## Подключение другого OpenAI-совместимого клиента

Для Open WebUI, LiteLLM или другого OpenAI-совместимого клиента укажите:

```text
Base URL: http://127.0.0.1:9655/v1
Model: deepseek-chat или другой доступный режим
API key: local-key, если клиент не позволяет оставить поле пустым
```

Bridge на `127.0.0.1` не требует этот фиктивный ключ. Не вставляйте в клиент token или cookie из `deepseek-auth.json`.

## Поддерживаемые маршруты

Обычные ответы и streaming SSE поддерживаются основными completion-маршрутами.

| Метод и маршрут | Назначение |
| --- | --- |
| `POST /v1/chat/completions` | OpenAI Chat Completions |
| `POST /v1/responses` | OpenAI Responses API |
| `POST /v1/messages` | Anthropic Messages API, включая Claude Code |
| `POST /v1/messages/count_tokens` | Локальная приблизительная оценка входных токенов |
| `GET /v1/models` | Список доступных моделей |
| `GET /v1/model-capabilities` | Доступность reasoning и поиска |
| `GET /v1/sessions` | Безопасные сведения о локальных сессиях |
| `GET /health` | Проверка работы HTTP-сервера |
| `GET /readyz` | Проверка наличия auth-файла с token и cookie |

Корневой адрес Anthropic-клиента: `http://127.0.0.1:9655`. Корневой адрес OpenAI-клиента обычно включает `/v1`.

## Как работают инструменты

Bridge сам не читает файлы, не запускает команды и не выполняет MCP-инструменты. Цикл выглядит так:

1. модель запрашивает инструмент;
2. Bridge передаёт запрос Claude Code, OpenCode или другому клиенту;
3. клиент решает, можно ли выполнить инструмент, и выполняет его в рамках своих разрешений;
4. клиент возвращает результат в Bridge;
5. Bridge передаёт результат модели, и она продолжает ответ.

Поддерживаются:

- OpenAI `tool_calls` и последующее сообщение с результатом инструмента;
- Anthropic `tool_use` и `tool_result`;
- Responses `function_call` и `function_call_output`.

Tool call принимается только как один строгий JSON-вызов разрешённого клиентом инструмента. Bridge проверяет имя, arguments, размер, вложенность и опасные ключи. Неизвестные инструменты, повреждённый JSON, Markdown-примеры и JSON внутри обычного текста не считаются вызовом.

Если модель вернула только reasoning без корректного tool call, Bridge может сделать один дополнительный запрос в той же сессии. Повтор требует либо один строгий вызов, либо финальный текст. Третьей попытки нет, поэтому бесконечный цикл не создаётся.

MCP-серверы и skills устанавливаются и настраиваются в Claude Code или OpenCode. Bridge видит их как обычные tools и только передаёт вызовы. Полная совместимость каждого стороннего MCP-сервера не гарантируется.

## Как работают сессии

- Заголовок `x-agent-session` сохраняет контекст конкретного клиента между запросами.
- Поля `metadata.user_id` и `user` также могут служить идентификатором клиента.
- Запросы без явного идентификатора изолируются друг от друга.
- Когда клиент возвращает результат инструмента, Bridge связывает его с исходной сессией по call id.
- Bridge не использует одну общую fallback-сессию для независимых клиентов.

Временные связи хранятся только в памяти процесса. После перезапуска Bridge лучше использовать стабильный `x-agent-session` для диалогов, которым нужно продолжение.

## Приблизительный count_tokens

Маршрут `POST /v1/messages/count_tokens` работает полностью локально и не отправляет запрос в DeepSeek.

Успешный ответ имеет вид:

```json
{"input_tokens": 123}
```

HTTP-заголовок ответа:

```text
x-deepseek-bridge-token-count: estimate
```

Это приблизительная консервативная оценка, а не официальный токенизатор Anthropic или DeepSeek. Она учитывает system, messages, обычный и многоязычный текст, thinking, tool calls, tool results и схемы инструментов, но может отличаться от реального количества токенов модели. Не используйте её как точное значение для биллинга.

## Безопасность

- `deepseek-auth.json` содержит доступ к вашей текущей сессии DeepSeek. Никогда не публикуйте, не коммитьте и не отправляйте этот файл другим людям.
- Не публикуйте папку `.chrome-profile-deepseek`: в ней находится отдельный Chrome-профиль авторизации.
- Bridge по умолчанию слушает только `127.0.0.1`.
- При внешнем `HOST` запуск блокируется без `PROXY_API_KEY` длиной не менее 24 символов.
- CORS разрешён для localhost и явно заданных адресов.
- Token, cookie, authorization и Bearer-значения удаляются из сообщений журнала ошибок.
- Bridge не сохраняет логин и пароль DeepSeek.
- Не отключайте TLS, CAPTCHA, 2FA или защиту браузера и не пытайтесь обходить ограничения DeepSeek.

## Ограничения проекта

- Проект зависит от внутренних маршрутов DeepSeek Web.
- DeepSeek может изменить API, PoW, WASM, лимиты или завершить веб-сессию.
- Offline-тесты подтверждают форматы API, streaming, строгий tool parser, ограниченный retry, tool result во всех трёх протоколах, разделение сессий и локальный count endpoint.
- После последних изменений финальная live-проверка полного цикла Claude Code и OpenCode ещё не завершена: последний doctor остановился на создании внутренней сессии с `fetch failed`.
- MCP и skills устанавливаются в самом CLI; Bridge не гарантирует совместимость каждого стороннего MCP.
- Подсчёт токенов приблизительный.
- Expert и V4 Pro сейчас недоступны.

## Диагностика ошибок

| Сообщение или проблема | Что делать |
| --- | --- |
| `DeepSeek streaming request failed` | Выполните `npm run doctor`. Если doctor указывает на авторизацию, вручную запустите `npm run auth`. |
| `fetch failed` | Проверьте, открывается ли `https://chat.deepseek.com` в обычном браузере, работает ли сеть и не мешает ли используемый VPN или прокси. Затем повторите `npm run doctor`. Не отключайте TLS. |
| HTTP 401 внутреннего API | Сессия обычно истекла или отклонена. Выполните `npm run auth`, затем doctor. |
| HTTP 403 внутреннего API | Повторите авторизацию вручную. Не путайте эту ошибку с отдельным HTTP 403 от главной публичной страницы. |
| `WASM load failed` | Проверьте сеть и доступ к ресурсам DeepSeek, затем повторите doctor. Не отключайте проверку TLS и не подменяйте случайные заголовки браузера. |
| `PoW failed` | Повторите doctor. DeepSeek мог изменить challenge или WASM; обходить защиту не нужно. |
| `Claude Code не найден` | Установите Claude Code, перезапустите Bridge и обновите панель через `Ctrl+F5`. |
| `OpenCode не найден` | Установите OpenCode, перезапустите Bridge и обновите панель через `Ctrl+F5`. |
| Порт 9655 занят | Закройте другое окно Bridge или программу, которая использует порт, затем снова запустите `START_DEEPSEEK.cmd`. |
| Модель не смогла сформировать tool call | Повторите или переформулируйте задачу и выберите `deepseek-reasoner`. Bridge уже делает максимум один безопасный корректирующий запрос. |

Не отключайте защиту DeepSeek, TLS или проверки браузера и не меняйте случайные браузерные заголовки ради обхода ошибки.

## Финальная ручная live-проверка перед merge

Этот чек-лист пока не выполнен после последних изменений. Запускайте его только с собственным аккаунтом и после проверки, что рабочее дерево Git чистое.

1. В папке Bridge выполните:

   ```powershell
   npm run doctor
   npm run test:live
   claude --version
   opencode --version
   ```

2. Создайте отдельную временную папку для Claude Code и файл `marker.txt` с уникальным текстом, например `CLAUDE_MARKER_2026`.
3. Запустите Claude Code через панель именно в этой папке.
4. Попросите прочитать `marker.txt` и вернуть точное содержимое. Убедитесь, что CLI реально вызвал инструмент чтения, вернул tool result и модель продолжила ответ.
5. Попросите сначала показать список файлов, а затем прочитать `marker.txt`. Убедитесь, что произошли два последовательных вызова инструментов и их call id/результаты не смешались.
6. Повторите пункты 2–5 в другой временной папке через OpenCode с другим маркером, например `OPENCODE_MARKER_2026`.
7. Откройте два отдельных тестовых сеанса с разными маркерами и убедитесь, что контекст и результаты одной сессии не появились в другой.

Не используйте для этой проверки рабочий проект, не разрешайте удаление файлов, установку пакетов или сетевые команды.
