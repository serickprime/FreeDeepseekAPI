# Результаты этапа 6

Дата: 2026-07-22. Ветка: `fix/agentic-tool-loop`.

## Устранённая проблема

Раньше `createProxyServer` выбирал ключ через `x-agent-session`, `metadata.user_id`, `user`, а при отсутствии всех трёх использовал общий литерал `default`. Независимые клиенты без идентификатора могли получить один объект `SessionStore`, одну удалённую DeepSeek-сессию и общий `parentMessageId`.

Теперь выбор вынесен в `lib/session_resolver.js`. Общий ключ `default` больше не создаётся.

## Выбор явной сессии

Приоритет сохранён:

1. `x-agent-session`;
2. `metadata.user_id`;
3. `user`.

Явное значение принимается только как непустая строка или число размером не более 128 байт. В памяти хранится не исходное значение, а SHA-256-derived непрозрачный ключ с указанием источника. Поэтому `/v1/sessions` не раскрывает исходный идентификатор. Если присутствующее значение не прошло ограничение, запрос получает новую анонимную сессию; resolver не переходит к менее приоритетному полю.

## Анонимные запросы

Каждый HTTP-запрос без явного идентификатора получает новый ключ `anonymous:<uuid>`. Последовательные и параллельные независимые запросы не используют одну сессию. Один корректирующий повтор этапа 4 остаётся внутри обработчика запроса и использует тот же объект сессии.

`SessionStore` ограничен 512 активными сессиями, удаляет просроченные записи и при заполнении вытесняет самую старую. Стандартный TTL сессии не изменён: 30 минут.

## Продолжение по call id

Когда Bridge возвращает строгий tool call, resolver временно связывает его идентификатор с уже выбранной сессией. Поддерживаются:

- OpenAI `tool_call_id`;
- Anthropic `tool_use_id` у блока `tool_result`;
- Responses `call_id` у `function_call_output`.

Follow-up без явного session id продолжает связанную удалённую сессию и сохраняет её `parentMessageId`. После успешного финального ответа соответствующая связь удаляется. Неизвестный, просроченный или недопустимый call id получает новую изолированную сессию.

Call id должен быть не длиннее 128 байт и соответствовать безопасному набору символов. Из одного результата учитываются максимум 16 уникальных идентификаторов. Карта содержит максимум 512 связей, TTL одной связи — 10 минут; просроченные и самые старые записи удаляются. Ключи не строятся из prompt, reasoning, cookie, token или authorization.

## Оставшиеся ограничения

- Анонимное продолжение возможно только пока процесс Bridge работает и временная связь call id не истекла.
- После перезапуска Bridge анонимному клиенту нужен явный session id либо новый диалог.
- Если follow-up содержит несколько известных call id, связанных с разными сессиями, resolver безопасно создаёт новую анонимную сессию.
- Этап 5 по-прежнему подтверждён только offline: последний doctor остановился на создании внутренней DeepSeek-сессии с `fetch failed`.
