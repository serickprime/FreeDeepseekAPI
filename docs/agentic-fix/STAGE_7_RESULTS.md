## Как подтверждён контракт

В локальном бинарнике найдены и проверены встроенные реализации Anthropic SDK и Claude Code:

- стабильный SDK-метод `messages.countTokens(body)` выполняет `POST /v1/messages/count_tokens` и передаёт полученное тело без преобразования;
- beta-вариант использует `POST /v1/messages/count_tokens?beta=true` и beta-заголовок token counting;
- внутренняя функция Claude Code формирует для подсчёта объект из `system`, `messages`, `tools`, добавляет сопоставленное поле `model` и выполняет `POST` на `${ANTHROPIC_BASE_URL}/v1/messages/count_tokens`;
- запрос использует JSON, `anthropic-version: 2023-06-01` и настроенную авторизацию; значения заголовков не выводились;
- успешный результат читается только когда `input_tokens` имеет числовой тип;
- встроенный Anthropic-compatible формат ошибки имеет вид `{ "type": "error", "error": { "type": "...", "message": "..." } }` с соответствующим HTTP-статусом.

Поле `model` обязательно по контракту SDK. `system` передаётся строкой либо массивом content blocks. `messages` содержит роли `user`/`assistant`, а `content` — строку либо массив блоков. `tools` передаются определениями с `name`, опциональным `description` и JSON Schema в `input_schema`.

### Подтверждено локальным Claude Code probe

Один разрешённый неинтерактивный probe был выполнен против временного HTTP-сервера на `127.0.0.1`. Были включены `--bare`, `--safe-mode`, отключены persistence, tools, telemetry, error reporting, auto-update и необязательный трафик. Сервер сохранял только метод, путь, имена заголовков и форму JSON; тексты prompt и значения authorization не записывались.

Probe завершился с кодом 0 и получил локальный mock-ответ. Эта минимальная команда не вызвала `count_tokens`: она сделала `HEAD /` и два `POST /v1/messages?beta=true`. Обычный Messages-запрос реально содержал `model`, массив `system` из `text`-блоков, массив `messages` с `text`-блоками и `tools: []`; также присутствовали `max_tokens`, `metadata`, `thinking`, `output_config` и `context_management`. Поэтому факт автоматического вызова `count_tokens` конкретно этим простым CLI-сценарием не заявляется. Контракт count endpoint подтверждён локальным исполняемым кодом SDK/Claude Code, а не сетевым предположением.

## Реализованный endpoint

Добавлен `POST /v1/messages/count_tokens`.

Успешный ответ:

```json
{"input_tokens":123}
```

`input_tokens` всегда целое неотрицательное число. Дополнительный HTTP-заголовок `x-deepseek-bridge-token-count: estimate` явно сообщает, что это локальная оценка, а не официальный результат токенизатора.

Ошибки возвращаются в Anthropic-compatible формате. Пустое тело без `model`/`messages`, повреждённый JSON, неверный метод и превышение существующего лимита размера обрабатываются предсказуемо и без включения пользовательских данных в сообщение.

Маршрут расположен до выбора session key и completion-маршрутов. Он не вызывает `completeImpl`, не загружает auth, не создаёт локальную или удалённую DeepSeek-сессию, не меняет `SessionStore`, не решает PoW, не создаёт call id и не запускает retry этапа 4. CORS, внешний `PROXY_API_KEY` и общий лимит тела применяются до маршрута штатной логикой сервера.

## Локальная оценка токенов

В проекте нет официального токенизатора Anthropic или DeepSeek, поэтому результат нельзя считать точным или использовать как подтверждённый биллинг. Алгоритм детерминирован и намеренно консервативен:

- ASCII-буквы и цифры оцениваются примерно плотнее одного токена на четыре символа;
- пунктуация и структура получают дополнительную стоимость;
- русский и другие многобайтовые алфавиты учитываются по UTF-8 размеру;
- китайские, японские и корейские символы учитываются не менее чем по одному токену;
- emoji получают повышенную стоимость;
- отдельно учитываются system, роли и служебная структура сообщений;
- поддерживаются `text`, `thinking`, `redacted_thinking`, `tool_use`, `tool_result`;
- учитываются имя/описание инструмента и вложенная `input_schema`;
- image block получает фиксированную стоимость 1024 токена без обхода base64;
- неизвестный block получает фиксированную стоимость 64 токена.

Ограничения выполнения: глубина 32, максимум 20 000 обрабатываемых узлов и максимум 262 144 UTF-16 единицы на одну строку. Циклы, массивы, необычные объекты и превышение глубины завершаются фиксированной ограниченной стоимостью. Сторонние зависимости и выполнение кода не используются.
