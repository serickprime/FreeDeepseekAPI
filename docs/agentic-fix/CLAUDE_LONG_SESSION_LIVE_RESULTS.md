# Результаты live-диагностики длинной сессии Claude Code

Дата проверки: 2026-07-22  
Проверенный commit: `0c8d950aa7dcf033206664a40f9031fa2862f63d`  
Node.js: `v24.12.0`  
Claude Code: `2.1.217`

## Условия эксперимента

- Bridge запущен из ветки `fix/claude-long-session-tools` с `BRIDGE_TOOL_DIAGNOSTICS=1`.
- Перед экспериментом полный `npm.cmd run doctor` прошёл успешно.
- Claude Code работал неинтерактивно через локальный Bridge с моделью `deepseek-reasoner`.
- Клиенту были разрешены только `Read`, `Glob` и `Grep`; изменяющие файлы, командные и сетевые инструменты были запрещены.
- Использовалась одна новая Claude Code session ID и двенадцать последовательных запусков с `--resume`.
- Временная папка содержала только двенадцать синтетических текстовых файлов и read-only правила. Пользовательские проекты и данные не использовались.
- Выполнен ровно один live-эксперимент. `npm run test:live`, OpenCode и дополнительные запросы к DeepSeek не запускались.

## Наблюдения Bridge

- Выполнено 12 пользовательских ходов и 17 запросов к `POST /v1/messages`.
- Во всех 17 запросах `protocol` был `anthropic`, а `stream` — `true`.
- Поле `tools` присутствовало во всех запросах и всегда имело форму массива.
- `raw_tool_count` и `normalized_tool_count` всегда были равны 3.
- Безопасный список имён не менялся: `Glob`, `Grep`, `Read`.
- Зафиксировано 5 строгих tool call и 5 следующих за ними запросов с одним tool result.
- Все 12 пользовательских ходов завершились классификацией `final_text` после нуля или нескольких tool call.
- Reasoning присутствовал в 14 из 17 ответов, content — во всех 17.
- `reasoning_retry_attempted` и `repeated_tool_retry_attempted` ни разу не включались.
- Сырой JSON tool call как обычный текст диагностикой не подтверждён.
- Зацикливание не наблюдалось; лимиты 12 ходов, 40 запросов и 20 минут не были превышены.

Диагностика Bridge подтверждает наличие разрешённых `Read`, `Glob` и `Grep` во всех запросах, но сохранённая запись `tool_response` намеренно не содержит имя выбранного инструмента. Поэтому по одному оставшемуся безопасному журналу нельзя независимо утверждать, что каждый из трёх инструментов действительно был выполнен. Надёжно подтверждены пять вызовов разрешённых инструментов и пять возвратов tool result.

## Сессии

Ожидавшийся единый `session_ref` на протяжении Claude Code session не сохранился:

- каждый из 12 новых пользовательских ходов пришёл без поддерживаемого Bridge идентификатора и получил `session_source: anonymous`;
- у 12 ходов было 12 разных временных `session_ref`;
- внутри каждого tool cycle связь сохранялась: 5 запросов с tool result получили `session_source: tool_result` и тот же `session_ref`, что соответствующий tool call.

Таким образом, `--resume` сохранял клиентскую сессию Claude Code, но Claude Code не передал Bridge поддерживаемый стабильный идентификатор между отдельными HTTP-цепочками. Bridge корректно продолжал удалённую сессию по call id только до финального ответа текущего tool cycle.

## Recap и compaction

В структурированном выводе Claude Code не было явного события recap или compaction. В пределах 12 ходов естественная compaction не произошла либо не была обозначена подтверждённым структурированным событием. Поэтому:

- compaction не подтверждён;
- поведение `tools` именно после compaction не проверено;
- обычный короткий summary или финальный текст не считались доказательством compaction.

## Новая независимая задача

После восьмого хода был выполнен предусмотренный планом независимый девятый ход. На уровне Bridge он получил тот же неизменный список tools и завершился `final_text`; признаков исчезновения tools, сырого JSON или retry не было. Сохранённый безопасный журнал не содержит текст результата, поэтому точное совпадение маркера намеренно не включено в отчёт.

## Гипотезы

Подтверждено:

- Claude Code 2.1.217 в этом эксперименте не удалял и не менял формат tools на протяжении 12 ходов;
- немедленная потеря tools после tool result не воспроизвелась;
- Bridge сохранял сессию внутри tool continuation по call id;
- между отдельными пользовательскими ходами одной Claude Code session Bridge создавал новые анонимные удалённые сессии.

Опровергнуто для этого ограниченного сценария:

- tools обязательно исчезают просто из-за нескольких последовательных ходов;
- reasoning-only или repeated-tool retry обязательно вызывают наблюдаемое поведение.

Осталось неподтверждённым:

- что происходило бы с tools после настоящей compaction/recap;
- была ли исходная пользовательская проблема вызвана именно compaction;
- вызывает ли отсутствие стабильной удалённой сессии потерю контекста в реальном длительном интерактивном сеансе;
- были ли фактически выполнены все три типа инструментов, поскольку безопасный Bridge-журнал не хранит имя выбранного tool call.

## Вывод и следующий этап

На основании этого этапа нельзя добавлять capability cache, восстанавливать старый список tools или увеличивать число retries: входной список tools оставался полным и стабильным. Обоснованный следующий этап — отдельно спроектировать минимальную совместимую передачу стабильного идентификатора Claude Code session в Bridge либо безопасное серверное сопоставление последовательных Anthropic-запросов. До изменения кода нужно проверить, есть ли в текущем HTTP-контракте Claude Code безопасный стабильный признак для такого сопоставления. Отдельная воспроизводимая проверка настоящего compaction всё ещё необходима.

Рабочая логика Bridge в этом этапе не изменялась.
