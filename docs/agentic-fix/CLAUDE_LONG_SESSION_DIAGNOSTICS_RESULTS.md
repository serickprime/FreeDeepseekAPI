# Результаты этапа 1: диагностика tools в длинных сессиях

Дата: 2026-07-22.

Проверяемая ветка: `fix/claude-long-session-tools`.

## Что добавлено

В Bridge добавлена выключенная по умолчанию диагностика метаданных tool-запросов. Она включается только для текущего процесса:

```powershell
$env:BRIDGE_TOOL_DIAGNOSTICS="1"
npm start
```

Диагностика пишет однострочные JSON-записи `tool_request` и `tool_response` через существующий logger. Исключение внутри logger перехватывается и не влияет на HTTP-запрос.

## Разрешённые поля

Для запроса фиксируются только:

- протокол, маршрут, модель и признак streaming;
- безопасный источник сессии и непрозрачный `session_ref`;
- наличие и форма поля `tools`;
- исходное и нормализованное количество tools;
- ограниченный список очищенных имён tools;
- признак продолжения после tool result и количество распознанных результатов.

Для ответа фиксируются только:

- найден ли строгий tool call;
- были ли непустыми reasoning и content;
- выполнялся ли reasoning-only retry;
- выполнялась ли коррекция точного повтора tool call;
- итог `tool_call`, `final_text`, `safe_failure` или `upstream_error`.

## Что журналировать запрещено

В диагностические записи не передаются prompt, system, messages, reasoning, content ответа, arguments, tool result, описания tools, JSON Schema, token, cookie, authorization, `PROXY_API_KEY`, HTTP headers, пользовательские пути, имена и содержимое файлов, полный call id, полный session id и внутренний ключ `SessionStore`.

Имена tools ограничены 32 элементами и 128 символами. Управляющие символы удаляются. Значение неправильного типа заменяется маркером `invalid`.

## Безопасный session_ref

`session_ref` — первые 12 hex-символов HMAC-SHA-256 от внутреннего ключа сессии. Ключ HMAC создаётся случайно в памяти при запуске процесса и не сохраняется на диск. Поэтому одинаковую сессию можно сопоставлять только внутри одного запуска Bridge, а исходный `x-agent-session`, `metadata.user_id`, `user` или ключ хранилища из записи восстановить нельзя.

## Offline-сценарий длинной сессии

Тест через реальный `createProxyServer` и mock `completeImpl` моделирует:

1. запрос с `Read`, `Write`, `Edit`, `Grep`, `Glob` и обычный финальный ответ;
2. следующий запрос с тем же списком и строгий `Read` tool call;
3. возврат настоящего tool result и финальный ответ;
4. запрос после условного recap без поля `tools`, когда mock возвращает строгий JSON `Read`;
5. новый запрос с tools и один reasoning-only retry;
6. отдельную клиентскую сессию.

Тест подтверждает одинаковый `session_ref` для одной явной сессии, другой `session_ref` для другой сессии, корректные counts/names, признаки continuation/retry/outcome и отсутствие закрытых данных в журнале. Отдельно проверены OpenAI, Anthropic и Responses, включая streaming.

## Что показал запрос без tools

Когда поле `tools` отсутствует, диагностика показывает:

- `tools_field_present: false`;
- `tools_field_shape: "absent"`;
- `raw_tool_count: 0`;
- `normalized_tool_count: 0`;
- пустой `tool_names`.

При текущем поведении строгий JSON `Read` в таком ответе не проходит allowlist и возвращается как обычный `final_text`. Это воспроизводит наблюдаемый класс симптома, но не доказывает, что Claude Code 2.1.217 действительно отправляет такой запрос после реального recap.

## Какие гипотезы теперь можно проверить

Будущая отдельная live-диагностика сможет безопасно показать:

- присутствует ли `tools` в проблемном запросе Claude Code 2.1.217;
- меняется ли форма поля или число нормализованных tools;
- остаётся ли запрос в той же сессии;
- был ли ответ распознан как строгий tool call;
- срабатывал ли один из уже существующих ограниченных retries.

Причина проблемы на этом этапе не объявляется найденной.

## Что намеренно не менялось

Не менялись выбор сессии, `parentMessageId`, история, prompt и continuation prompt, строгий parser, allowlist tools, retries, streaming, форматы OpenAI/Anthropic/Responses, `count_tokens`, doctor, launcher, панель, авторизация, PoW, WASM и обращения к DeepSeek. Capability cache не создавался, старый список tools не переиспользуется.
