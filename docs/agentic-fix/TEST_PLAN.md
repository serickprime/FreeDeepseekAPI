# План тестирования agentic-исправлений

Live-тесты никогда не входят в `npm test` и не запускаются без явного согласия пользователя. Они используют только собственную авторизацию пользователя и не должны печатать или сохранять секреты.

## Unit: без сети и аккаунта

- Парсер OpenAI/Anthropic/Responses: обычный OpenAI-ответ, Anthropic Messages и Responses API в их адаптерах.
- Streaming-адаптеры: OpenAI streaming, Anthropic streaming и Responses streaming; порядок start/delta/finish, закрытие SSE и безопасный error-event.
- Модели: Chat, Reasoner, Chat Search и Reasoner Search корректно превращаются в доступные конфигурации; неподдерживаемые aliases отклоняются.
- Tool parser: валидный вызов без streaming и с streaming; неизвестный вызов отклоняется; сломанный, неполный и слишком большой JSON не проходит; обычный пример JSON в тексте не считается tool call.
- Reasoning без tool call: фикстура не должна превращаться в молчаливый `end_turn` там, где этап 4 требует ограниченный повтор; повтор не превышает установленный лимит.
- Безопасность: upstream-ошибка авторизации и streaming-ошибка не содержат token/cookie в клиентском тексте или локальном журнале; PoW/WASM-ошибки имеют безопасный идентификатор журнала.
- Сессии: две параллельные сессии имеют разные `id`/`parentMessageId`; сокращение истории сохраняет последнее задание и последние результаты tools; явный `x-agent-session` остаётся совместимым.

## Integration: локальный HTTP-сервер с mock DeepSeek

- `POST /v1/chat/completions`: JSON и SSE, включая reasoning и корректные OpenAI `tool_calls`.
- `POST /v1/messages`: JSON и SSE в Anthropic-формате, `tool_use`, последующий `tool_result`, затем продолженный ответ.
- `POST /v1/responses`: JSON и SSE с output-text/reasoning и function-tool форматом.
- Инструменты не исполняются Bridge: mock фиксирует, что сервер не запускает команды, а только возвращает описания вызовов.
- Сценарий дополнительного запроса: первый mock-ответ содержит reasoning без допустимого call, второй — строгий call или финальный текст; третий upstream-вызов запрещён.
- Doctor с подменёнными transport/WASM: создание сессии, challenge, ошибка загрузки WASM, ошибка solve PoW, completion, обычный разбор и streaming-разбор.
- Ошибки 401/403/429/5xx, `Retry-After`, timeout и повреждённый stream возвращают безопасный протокольный ответ и локальный диагностический след.
- `count_tokens`: после выбора контракта — позитивный и негативный contract-test.

## Live: только по явному согласию пользователя

Перед запуском: `git status --short`, проверка, что `deepseek-auth.json` игнорируется, и явное подтверждение пользователя. Запускать вручную `npm run test:live` либо отдельные минимальные сценарии; не добавлять в CI и не вызывать из doctor автоматически.

- Реальный DeepSeek Chat: обычный OpenAI ответ и streaming.
- Реальный DeepSeek Reasoner: обычный ответ и reasoning streaming.
- Реальные DeepSeek Chat Search и Reasoner Search: по одному малому запросу на режим, с фиксацией только обезличенного результата.
- Реальный tool call без streaming и со streaming: инструмент передаётся клиентом, модель возвращает строго разрешённый вызов, Bridge его не исполняет.
- Claude Code читает реальный безопасный файл тестового проекта, затем получает tool result и продолжает ответ.
- OpenCode читает тот же безопасный файл, затем получает tool result и продолжает ответ.
- Если установлен MCP: проверить только один безопасный read-only tool, но не обещать поддержку стороннего MCP без отдельного результата.

## Критерии приёмки

Исправление можно считать готовым только если все unit/integration тесты проходят, live-результаты получены с согласия пользователя, reasoning-only случай не завершает агентскую задачу молча, а ни логи, ни ошибки, ни Git-статус не содержат credential-данных.
