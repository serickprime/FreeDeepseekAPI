# Результаты этапа 5

Дата проверки: 2026-07-22. Ветка: `fix/agentic-tool-loop`.

## Что исправлено

Offline integration-тесты подтвердили, что прежняя нормализация теряла связь между вызовом и результатом инструмента:

- OpenAI-сообщение `role: tool` теряло `tool_call_id` и имя, а `assistant.tool_calls` не попадали в prompt.
- Anthropic `tool_use.id` не включался в prompt, хотя `tool_result.tool_use_id` передавался частично.
- Responses `function_call` и `function_call_output` не распознавались; follow-up мог быть отклонён как пустой ввод.

В `server.js` добавлено текстовое представление `[Tool Call]` / `[Tool Result]`, которое сохраняет имя инструмента, `call_id`, arguments и результат. Возвращённые Bridge идентификаторы сопоставляются с именами внутри уже выбранной локальной сессии; хранится не более 32 сопоставлений. Это не является локальной историей диалога и не выполняет инструмент.

## Проверенные протоколы

- OpenAI Chat Completions: `assistant.tool_calls` → выполнение клиентом → `role: tool` с `tool_call_id` → финальный ответ. Follow-up также проверен в SSE.
- Anthropic Messages: `tool_use` → выполнение клиентом → `tool_result` с `tool_use_id` → финальный ответ.
- OpenAI Responses: `function_call` → выполнение клиентом → `function_call_output` с `call_id` → финальный ответ. Имя восстанавливается по сессионному сопоставлению даже когда follow-up содержит только `function_call_output`.

Во всех сценариях использовался один `x-agent-session`. Отдельный тест подтверждает, что разные явные `x-agent-session` получают разные объекты сессии. `parentMessageId` сохраняется клиентом DeepSeek в объекте сессии и используется следующим completion-запросом.

- регрессия обычных запросов без tools.

## Что подтверждено автоматически

- Bridge только возвращает описание вызова и не выполняет инструменты.
- Tool result доходит до следующего mock completion с именем, идентификатором и результатом.
- Финальный ответ возвращается клиенту во всех трёх API-форматах.
- Два последовательных вызова не смешивают call id и arguments.
- Ограниченный retry этапа 4 не превращается в agentic loop.
- Строгий parser этапа 3 не изменялся.

## Ограничения и ручная проверка

- Реальный DeepSeek tool-result цикл ещё не подтверждён из-за сетевой ошибки создания сессии во время doctor.
- После восстановления доступности внутреннего API нужно сначала успешно выполнить `npm run doctor`, затем один раз `npm run test:live`.
- После успешного live API следует проверить `claude --version`, `claude --help`, `opencode --version`, `opencode --help`. Безопасный неинтерактивный тест допустим только во временной папке с отдельным `marker.txt` и ограниченным временем.
- Сессионное сопоставление call id хранится только в памяти процесса и ограничено 32 последними вызовами.
- Неявная общая сессия `default` остаётся предметом будущего этапа 6.
