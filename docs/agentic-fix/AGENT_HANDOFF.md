# Передача следующему агенту

## Что уже изучено

Изучены README, package/сервер/клиент, parser и streaming-адаптеры, сессии, панель setup, модели, doctor, live smoke-тест, unit-тесты, OpenCode-конфиг, `.gitignore` и история Git. Текущее документированное состояние зафиксировано в остальных файлах этой папки.

Главная проблема: при наличии tools модель иногда выражает намерение вызвать инструмент в `reasoning`, но Bridge ищет строгий call только в `output.content`. Результат без call превращается в обычное завершение, поэтому CLI агент не получает запрос на инструмент.

## Безопасный порядок работы

1. Начать с этапа 1 из [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md), а не с переписывания архитектуры.
2. Перед изменениями выполнить `git status --short`, `git branch --show-current`, `git log --oneline -10` и `npm test`. Если дерево не чистое, остановиться и спросить пользователя.
3. Не менять без тестов `server.js`, `client.js`, `lib/tool_parser.js`, `lib/api_stream.js`, `lib/session.js`, `scripts/doctor.js`, `scripts/live_agentic_smoke_tests.mjs`, `tests/unit.test.js`, `opencode.json` и `package.json`.
4. Делать один маленький этап — один понятный commit. Перед commit показать список файлов и `git diff --check`; не использовать reset, restore, clean, force push или merge без отдельного указания.
5. После каждого этапа агент обязан остановиться, показать изменения, результаты тестов и дождаться подтверждения пользователя.

## Тесты и совместимость

- После каждого изменения запускать `npm test`; обновлять `PROJECT_STATUS.md` и `NEXT_STEP_PROMPT.md` согласно `AGENTS.md`.
- `npm run test:live` допустим только после явного согласия пользователя в текущем диалоге. Не запускать авторизацию, Chrome или запросы DeepSeek «для проверки» без такого согласия.
- Сохранять OpenAI Chat Completions, OpenAI Responses и Anthropic Messages/SSE обратную совместимость. Bridge передаёт tool call вызывающему агенту; он никогда не выполняет shell-команды, файловые действия или MCP tools сам.
- Не считать текст, reasoning или пример JSON настоящим вызовом. Принимать только строго валидный, разрешённый клиентом и ограниченный по размеру tool call.

## Секреты и GitHub

- Никогда не читать содержимое, не выводить, не копировать и не коммитить `deepseek-auth.json`, `.env`, cookies, token или Chrome-профиль `.chrome-profile-deepseek/`.
- До commit проверять `git status --short` и `git check-ignore deepseek-auth.json .chrome-profile-deepseek`; при неожиданном файле остановиться.
- Не публиковать изменения, не делать push и не менять видимость репозитория без отдельного разрешения пользователя.

Следующий агент не должен сразу переписывать архитектуру целиком. Сначала реализовать безопасную диагностику из этапа 1, покрыть её тестами и дождаться подтверждения пользователя.
