# Claude mandatory Read compaction live results

Дата проверки: 2026-07-23

Проверенный commit: `aa9981992489c61b7f145c37eb324da7d8fd57e7`

Node.js: `v24.12.0`

Claude Code: `2.1.217`

## Результат

Классификация: **MODEL_SKIPPED_TOOL**

Выполнен ровно один фактический live-сеанс Claude Code с новой session ID через актуальный Bridge и `BRIDGE_TOOL_DIAGNOSTICS=1`. Разрешён был только `Read`; `x-agent-session` и `ANTHROPIC_CUSTOM_HEADERS` не устанавливались.

До фактического сеанса временный контроллер завершил собственную предзапусковую проверку из-за формата служебного файла. Было отдельно подтверждено, что Claude Code не запускался, временный проект ещё не был создан и число `POST /v1/messages` оставалось равным нулю. После исправления только временного контроллера был выполнен один разрешённый live-сеанс. Файлы репозитория и Bridge при этом не менялись.

Единственный разрешённый запуск `npm.cmd run doctor` полностью прошёл все стадии: загрузку авторизации, проверку DeepSeek Web, создание remote session, challenge, загрузку и компиляцию WASM, PoW, completion и streaming.

## Границы эксперимента

- Подготовлено 18 синтетических chunk-файлов общим размером 576000 байт, отдельный небольшой post-compaction файл и `CLAUDE.md`.
- До эксперимента были сохранены список, размеры и SHA-256 всех 20 временных файлов.
- Фактически выполнен один основной пользовательский ход.
- Bridge получил один `POST /v1/messages`.
- Второй ход, resume и ход после compaction не запускались.
- Явный recap или compaction не произошёл.
- Лимиты 18 основных ходов, 40 запросов и 30 минут не достигались.

## Безопасная диагностика

Единственный запрос:

| Client | Client source | Upstream | Upstream source | Continuation | Tool result |
|---|---|---|---|---|---:|
| C1 | `claude_header` | U1 | `anonymous` | нет | 0 |

Поля запроса:

- `tools_field_present = true`;
- `tools_field_shape = array`;
- `raw_tool_count = 1`;
- `normalized_tool_count = 1`;
- `tool_names = [Read]`;
- `is_tool_continuation = false`.

Поля ответа:

- `strict_tool_call_detected = false`;
- `reasoning_nonempty = true`;
- `content_nonempty = true`;
- `reasoning_retry_attempted = false`;
- `repeated_tool_retry_attempted = false`;
- `outcome = final_text`.

Bridge передал Claude Code актуальный allowlist с одним `Read`, но модель вернула обычный финальный content без строгого tool call. Поэтому настоящий `Read` не выполнялся, `tool_result` не возвращался и правильный маркер получить было невозможно. Ответ `TOOL_UNAVAILABLE`, сырой JSON tool call, запрещённый инструмент, повтор tool call и цикл не наблюдались.

## Проверяемые инварианты

- Нативная client identity присутствовала: `client_session_source = claude_header`, условное обозначение — C1.
- Стабильность C1 между ходами не проверена, поскольку эксперимент безопасно остановлен после первого хода.
- Первый обычный запрос получил новую anonymous upstream identity U1.
- Stateless-семантика между несколькими обычными ходами не проверена.
- Tool continuation не проверена, поскольку tool call не возник.
- Tools до compaction присутствовали и имели ожидаемую форму и количество.
- Tools в связи с compaction и после compaction не проверены.
- Обязательный `Read` после compaction не выполнялся.
- Переключение на независимую post-compaction задачу не проверено.
- Старый план модель не продолжала: post-compaction ход не запускался.

## Сохранность временных данных

После остановки эксперимента повторно проверены список, размеры и SHA-256 временных файлов. Состав временной папки и все файлы остались неизменными. Синтетические маркеры, содержимое файлов, tool payloads, идентификаторы и полный диагностический журнал в этот отчёт не включены.

## Вывод

Эксперимент не достиг recap или compaction и не дал новых данных о поведении после сокращения контекста. Причиной ранней остановки было не исчезновение tools: Bridge передал корректный массив с единственным `Read`, однако модель пропустила обязательный инструмент в этом конкретном ответе.

Результат не обосновывает изменение Bridge, добавление retries, capability cache, восстановление allowlist или постоянную upstream-сессию. Текущая реализация корректно сохранила разделение client и upstream identity и доставила актуальный tool allowlist в единственном наблюдавшемся запросе, но длинная post-compaction цепочка остаётся непроверенной.

Повторять эксперимент автоматически нельзя. Любая следующая live-проверка потребует отдельного решения и отдельного разрешения; перед ней следует определить, принимается ли наблюдаемая вариативность модели либо требуется отдельное исследование надёжности выбора инструмента без изменения session routing.
